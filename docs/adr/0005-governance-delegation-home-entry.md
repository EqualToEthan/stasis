# 首页治理委托入口与质押文案统一

## 背景

Cardano Conway 时代后，质押（Stake Pool delegation）与治理委托（DRep delegation）是两类独立的链上证书。观察钱包原有 UI 把 Stake Pool 操作和 DRep 操作都混称为「委托」，造成用户困惑：

- `StakingScreen` 里输入 Stake Pool ID 的操作被标注为「委托」。
- 同一页面还展示了「DRep 委托」状态卡。
- DRep 弃权当前随质押交易自动完成，没有独立的展示入口。

产品侧希望：

1. 把 Stake Pool 相关操作统一称为「质押」，DRep 相关操作统一称为「治理委托」。
2. 把「治理委托」提升到首页，与「质押」平级。
3. 首次质押用户无感知地完成弃权，不需要手动设置。

## 决策

1. **术语统一**
   - Stake Pool 操作：「质押」。
   - DRep 操作：「治理委托」。
   - 相应更新 `CONTEXT.md` 术语表。

2. **首页入口**
   - 首页操作区保持两行布局：
     - 第一行：发送、收款。
     - 第二行：质押、治理委托。
   - 「治理委托」入口始终显示，不随链上状态隐藏。

3. **质押页面（`StakingScreen`）**
   - 页面标题从「质押管理」改为「质押」。
   - 移除 DRep 状态卡，只展示 Stake Pool 相关状态（注册、当前质押池、可提取奖励）。
   - Tab「委托」改为「质押」，按钮「构建委托交易」改为「构建质押交易」。
   - 所有文案、注释中的「委托」统一改为「质押」。
   - 质押交易继续自动附带 `voteDelegation(abstain)` 证书，并在 UI 提示用户「本交易将同时完成 stake key 注册、Stake Pool 委托和弃权（默认不参与治理）」。

4. **治理委托页面（`GovernanceDelegationScreen`）**
   - 新建页面：`coldwallet-watch/lib/screens/governance_delegation_screen.dart`。
   - 路由：`/governance-delegation`。
   - **只读展示页**，不提供操作按钮。
   - 显示当前治理委托状态：
     - 已默认弃权；
     - 未设置；
     - 已委托给外部 DRep（由外部工具操作）。
   - 页面说明文案：本应用当前仅支持默认弃权；质押时会自动完成弃权设置，无需手动操作。

5. **提取奖励**
   - 正常流程下，质押交易已自动附带弃权，提取奖励不会失败。
   - 存量账户或外部工具导致未弃权的异常情况，由链上错误原文兜底；本阶段不在提取奖励页面插入自动弃权流程。

## 考虑的选项

- **保持原 UI**：Stake Pool 和 DRep 操作都标注为「委托」，DRep 隐藏在质押管理页面。拒绝原因：术语混淆，与产品目标冲突。
- **把治理委托做成可操作页面**：提供「设为弃权」按钮，允许用户手动设置。拒绝原因：与「用户无感知」目标冲突；正常用户不应该需要进入该页面操作。
- **治理委托页面只读展示**：选中方案。既满足首页独立入口的透明度需求，又不把链上规则复杂性暴露给普通用户。

## 影响

- 需要修改 `StakingScreen` 文案并移除 DRep 状态卡。
- 需要新建 `GovernanceDelegationScreen` 并注册到路由表。
- 需要更新 `HomeScreen` 操作按钮布局。
- 需要更新 `CONTEXT.md` 术语表，将「DRep 委托」改为「治理委托」。
- 需要新增/更新测试覆盖首页、质押页面和治理委托页面。
- 不改变 `coldwallet-protocol` 协议层：质押交易继续自动附带 `voteDelegation(abstain)`，与 ADR 0004 保持一致。
