# ADR 0007: EVM 地址即身份（address-as-identity）

## 状态

已采纳（Accepted）

## 背景

EVM 链族中，同一个私钥在所有 EVM 链（BSC、Arbitrum、Base）上派生出**完全相同的地址**——地址由公钥的 Keccak-256 哈希后 20 字节决定，与链无关。

这与 Cardano 有本质区别：Cardano 不同网络（preview / mainnet）产生不同的地址。

在初始实现中，`WatchWallet` 模型为每个钱包条目保存 `address` + `chainId`，即"一个地址 + 一条链 = 一个钱包条目"。这意味着同一个 EVM 地址在不同链上需要分别添加 5 次，违反观察钱包"一眼看全貌"的核心价值。

## 决策

**EVM 钱包采用"地址即身份"模型**：

- 一个 EVM 地址 = 一个钱包条目，不绑定任何特定链
- `WatchWallet.chainId` 对 EVM 钱包设为 null，仅靠 `chainFamily = 'evm'` 标识
- Cardano 钱包保持现有模型（chainId 区分 preview / mainnet）

**首页 UI**：

- EVM 钱包通过链下拉列表（Dropdown）切换展示该地址在各链上的资产
- 下拉列表始终包含所有已支持的 EVM 链，后续新增链时自动扩展，无 UI 溢出风险
- 余额加载策略：当前选中链优先加载，其余链后台异步预填充
- EVM Send 按钮保持置灰（暂不实现发送功能）

**添加钱包流程**：

- EVM 钱包添加时不再需要选择链
- 用户只需输入名称和地址（或扫码），保存后自动在所有 EVM 链上查询余额

## 被否决的方案

| 方案 | 否决原因 |
|------|----------|
| 保持"地址+链=条目"（当前模型） | 用户需要把同一地址添加 5 次，体验差 |
| 混合模式（选主链 + 展开其他链） | 增加 UI 复杂度，主链概念对用户无意义 |
| Cardano 与 EVM 强制统一模型 | 地址派生机制本质不同，强行统一会误导用户 |
| 只显示有余额的链 Tab | RPC 延迟或失败时用户看不到某些链，造成困惑 |
| 链标签页（Tabs）切换 | 链数增加后 Tab 栏溢出，UI 扩展性差 |
| 全量并行加载所有链 | 5+ 条链同时发 RPC 可行，但当前链优先体验更好 |

## 后果

- **数据迁移**：现有 EVM 钱包的 `chainId` 字段在读取时忽略即可，无需主动迁移
- **向后兼容**：`WatchWallet.fromJson` 已对 `chainId` 做可选处理（`json['chainId'] as String?`），无需改动反序列化逻辑
- **RPC 开销**：从 1 条链增加到 5 条链的余额查询，但均为免费公共节点，可接受
- **冷钱包端不受影响**：coldwallet-app 的地址派生已返回 `Map<chainId, address>`，数据结构天然支持
